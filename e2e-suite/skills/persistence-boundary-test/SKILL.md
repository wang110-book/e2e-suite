# 持久化边界测试

## 家族契约（e2e-suite）

- phase: exec
- after: env
- inputs: 上轮持久化边界矩阵（回归基线，可选）、环境说明、**持久化声明清单**（哪些状态应跨重启保留/哪些应临时/哪些敏感字段必须加密）
- outputs: 持久化边界矩阵 + 重启前后成对证据 + 缺陷清单
- idempotent: yes（测试产生的状态变更结束时还原）

## 定位

系统总有一批状态"声称跨重启保留"（用户配置、偏好、激活状态），一批"声称临时"（会话、内存态、选中高亮）。持久化边界测试验证声明与实现一致——**留住的没留、该清的没清，都记缺陷**。

## 第一步：梳理持久化声明清单

从设计文档/配置结构/存储 schema 提炼三类清单（被测系统专属，不进本技能）：
1. **应持久**：用户设置、业务数据、激活/授权状态、节点/账号数据；
2. **应临时**：会话凭据、内存缓存、界面选中态、未保存草稿；
3. **敏感字段**：密码/密钥/凭据——必须以哈希/密文形态落盘，不出现明文。

## 四类边界用例

| 边界 | 操作 | 断言 |
|---|---|---|
| **重启边界** | 修改状态 → 记录 → 重启服务进程 → 复核 | 落盘文件/DB + API 回读 + UI 回显三侧一致 |
| **会话边界** | 修改状态 → 清浏览器存储/换浏览器/新会话 | 应持久的可重新登录恢复；应临时的已失效 |
| **升级边界** | 覆盖安装新版本（配置 onlyifdoesntexist 类策略） | 声明保留的用户数据仍在；声明重置的已重置；新旧 schema 兼容 |
| **崩溃边界** | 服务运行中强杀（模拟断电）→ 重启 | 半途状态按声明重置或恢复（状态机 halfway reset）；不产生损坏文件/锁残留 |

每条用例：`改状态 → 取 before 证据 → 边界事件 → 取 after 证据 → before/after 对照结论`。

## 断言纪律

- **成对取证**：before 与 after 走同一断言通道（同一 API、同一文件、同一查询），对照才成立。
- **双侧核对**：存储侧（文件/DB 真实内容）与呈现侧（API/UI 回显）都要验，防"存了但读不出"与"读的是默认值假象"。
- **敏感明文扫描**：对存储文件 grep 敏感字段明文（密码/token/密钥），命中即高危缺陷。
- **临时态反向验证**：临时状态在重启后必须消失，"意外持久"记缺陷（如选中高亮、未确认的操作）。

## 红线

- 重启/强杀有代价：确认无其他测试并行；用户数据先备份。
- 崩溃边界用例前先布防崩溃转储（顺带收集崩溃现场）。
- 测试结束时把被测状态还原到进入前的快照，并验证还原生效。

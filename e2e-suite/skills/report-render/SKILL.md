# 测试报告渲染

## 家族契约（e2e-suite）

- phase: report
- after: assert（默认最后执行）
- inputs: 本轮各成员的落盘产物（功能矩阵/证据原文/缺陷清单/环境说明/契约对照表）、版本与环境信息
- outputs: 正式测试报告（Markdown，可选 HTML）+ 归档文件
- idempotent: yes

## 定位

成员产出是"原料"（各自为政的矩阵、日志行、清单），本技能负责**汇总、去重、溯源、定稿**——产出一份读者（用户/未来的自己）不用翻聊天记录就能看懂并复核的报告。

## 报告骨架（固定结构）

```markdown
# XX 系统测试报告（版本 X.Y.Z · 日期 · 环境）
## 一、结论摘要（TL;DR）
   3-5 条：能不能用 / 几个高危 / 与上轮相比的变化 / 本轮种子命中率（家族健康度）
## 二、功能矩阵
   用例 × 结果（✓/✗/阻塞），按功能域分组，标注版本与环境
## 三、缺陷清单
   编号 | 现象（复现序列）| 根因 | 严重度 | 回归证据（修复后复跑记录）
## 四、专项结论
   反例/持久化/契约漂移等各成员的独立结论段
## 五、证据附录
   每条结论对应的日志行/API 响应/查询结果原文（可复核）
## 六、未覆盖项
   明说哪些维度没测到及原因
## 七、环境与产物
   版本、测试凭据状态、备份位置、各成员产物文件清单
## 八、元验证与进化
   种子命中率·假绿样本·本轮进化记录（取自 canary-calibration 的元指标与进化日志）
```

## 汇总纪律

1. **结论先行**：读者第一屏要能拿到"能不能用"；细节按需下钻。
2. **证据溯源**：每条结论必须能指到附录里的证据原文；成员报告与总报告不一致时以证据原文为准并标注冲突。
3. **不改写成员结论**：只汇总、分级、排重；对结论有怀疑标注"待复核"，不悄悄修改。
4. **缺陷严重度按用户影响分级**：高危=数据损坏/安全/假成功；中=功能不可用有绕行；低=体验与文档。
5. **失败项必附复现序列**；**未覆盖项明说**——报告的诚实性和通过项同样重要。

## 红线自检（交付前）

报告定稿前逐项核对成员执行完备度——漏项**写进结论摘要**（"自检漏项：X"），不悄悄省略：

- [ ] 各成员产物均落盘且路径已列进"七、环境与产物"（不依赖"我记得上一阶段做了什么"）；
- [ ] 破坏性/重启类用例有还原确认记录（用户态已还原并验证）；
- [ ] 每条缺陷附复现序列 + 证据原文；"应该没问题"式结论一律记为自检漏项；
- [ ] 未覆盖项已明说（哪些维度没测 + 原因）；
- [ ] 本轮执行计划与用户确认的计划一致；有偏离的显式注明；
- [ ] 元指标（canary 产出）已进报告"八、元验证与进化"；种子命中已标"（预期）"，未计入真实缺陷统计。

## 归档

- 文件名：`report-<系统>-<版本>-<日期>.md`，与证据附录一起落盘到版本库/测试目录；
- 报告中引用的产物文件列出路径清单，保证事后可回查；
- 修复闭环的回归结论追加到对应缺陷条目，不另起新报告。

# 用例集设计（design 槽位）

## 家族契约（e2e-suite）

- phase: design
- after: env
- before: exec
- inputs: 环境说明（env 类成员产物：观测入口/测试凭据/夹具/备份位置）、接口契约文档或契约对照表（家族契约盘点产物，任意来源）、本轮改动面说明、上轮用例集与缺陷清单（回归场景，可选）
- outputs: 本轮用例集文件（用例矩阵 + 用例卡片 + 断言通道分派 + 分级标记 + 未覆盖项，落盘、带版本号）
- idempotent: yes

## 定位（为什么独立成阶段）

exec 类成员原本"边跑边设计"——用例圈定靠临场判断，每轮从零开始，且没有可引用的回归基线。本技能把设计提出来独立落盘：

- exec 成员吃**本轮用例集**执行，不再临场猜测范围与断言通道；
- 上轮用例集保留为**回归基线**，"改了前后端后回归"时直接对照圈定；
- 用例集是产物（契约第 3 条要求的落盘产物之一），可人工评审、可独立重跑。

**产品专属用例不进本技能**（与执行类成员同哲学）：本技能提供设计方法与文件结构，具体用例内容落盘到被测系统的测试矩阵文档（用户指定位置，默认被测根下 `test-suite/` 目录）。

## 设计输入（先读齐四样，缺一先补）

1. **环境说明**：观测入口（日志路径/状态 API/DB 查询方式）、测试凭据、夹具清单——决定断言通道分派是否可执行；
2. **契约对照表**：有现成的直接用；没有则先完成盘点（读契约文档 + 前端请求代码 + 后端路由/解析代码产出对照表）——高危区标注（载荷序列化/字段大小写/静默降级）直接转化为必测用例；
3. **改动面说明**：改了哪些前后端模块、哪些承载产物重新部署、哪些 API 端点新增/变更；
4. **上轮用例集 + 缺陷清单**（回归场景）：上轮缺陷的修复用例本轮必测。

## 范围圈定：分级回归纪律（测多少）

| 级别 | 触发场景 | 内容 | 时长参考 |
|---|---|---|---|
| **冒烟** | 每轮必跑 | 核心业务主链路（产品本职功能），每域 1-2 条 | ≤30 分钟 |
| **定点** | 有改动面的常规轮 | 改动面映射到的功能域全量 + 上轮缺陷修复用例 + 冒烟 | 30-60 分钟 |
| **全量** | 版本里程碑 / 契约重大变更 / 持久化层变更 | 三维矩阵全格 | 按需 |
| **快验** | 热修后 | 受影响单条用例 + 1 条主链路用例 | ≤15 分钟 |

- 改动面 → 功能域映射必须显式写出：每个改动模块对应影响哪些域（认证/配置/核心业务/观测/权限），理由可核；
- 优先级纪律（家族公共口径）：核心业务主链路 > 配置面 > 观测面 > 边界反例；
- 拿不准是否全量时，向用户呈现圈定结果与理由，确认后再产出用例集。

## 用例生成：三维矩阵 × 设计技术（怎么挑点）

三维（家族公共口径）：**功能域 × 状态边界 × 正反方向**。
每格内用设计技术挑点，不穷举组合（矩阵保覆盖，技术保密度）：

| 技术 | 用在哪 | 规则 |
|---|---|---|
| **边界值分析（BVA）** | 数值/长度/阈值/配额类字段 | min、min+1、max、max−1、越界各取代表 |
| **等价类划分** | 输入域 | 有效/无效类各取一个代表值，不重复取同类 |
| **判定表** | 多条件组合（鉴权 × 状态 × 资源） | 取覆盖子集（正交或两两覆盖），不做全笛卡尔 |
| **状态迁移** | 状态机类（任务/连接/会话） | 声明的每条迁移各一用例 + 1-2 条非法跳转 |

每格产出 1-3 张用例卡片；高危区（契约对照表标注的）必须覆盖正反两向。

## 用例卡片格式（四要素 + 三项附加）

```
编号 TC-<模块>-NNN
前置状态 → UI 操作序列 → 后端断言（≥1 通道：指明通道+具体端点/日志关键词/DB 查询）→ 还原动作
附加：级别标记（冒烟/定点/全量）· "需还原"标记（破坏性/重启类，附还原命令）· 来源（新增/回归上轮缺陷 #X/高危区）
```

## 断言通道可执行性核对

- 每张卡片的断言通道必须**在本环境真实可执行**：端点存在（环境说明里已列，或只读探测确认过）、日志路径可读、DB 可查；
- 不写"应该有"的通道；不可执行时降级到更廉价的通道，并在卡片上标注"断言缺口：原拟通道 X，不可执行，改用 Y"；
- 权限类用例指定降权上下文（runas /trustlevel 或普通账户），与执行类成员同口径。

## 覆盖自查

- 哪些维度本轮未测 + 原因（随用例集进报告，与 blackbox"未覆盖项"同口径）；
- 契约高危区（序列化/大小写/静默降级）逐条核对：有对应用例，或显式标"本轮不测+理由"；
- 双向往返闭环各方向至少一条（前端改动→后端处理→前端回显；后端变化→前端反映）。

## 交付物结构

```
<被测系统>/test-suite/
  test-cases-vN.md    ← 本轮（版本号递增，禁止同名覆盖）
  test-cases-vN-1.md  ← 上轮保留（回归基线，只读）
```

`vN.md` 头部必含：环境（版本/观测入口）、本轮级别与范围圈定理由、用例矩阵汇总（功能域 × 级别 × 数量）、未覆盖项、缺陷回归用例编号映射。

## 测试集结算（自主迭代）

每轮执行 + 断言完成后，总控把本轮新发现的用例/缺陷模式交回本成员，按下述规则**晋升/合并/弃置**，生成 `test-cases-v(N+1)`——测试集越跑越通用，但**减法是策划**，不是越攒越长：

**晋升三条件（缺一不可）**：
1. **通用性**：可复用于同类其他系统，不依赖被测系统产品形态；产品专属模式 → 进该系统测试矩阵文档，不进通用集；
2. **可复现**：卡片四要素完整（前置/操作序列/可执行断言通道/还原），非一次性现象；
3. **不重复**：先比对既有卡片库，相似（同功能域 × 同边界类）则合并并继承证据，不追加新卡。

**防臃肿闸门**：
- 单次结算净增卡片 ≤ 5；超出按"严重度 × 复现次数"强制排序，只留前 5；
- 冒烟/主链路卡片是骨架：只更新（纠错），不追加（数量不涨）；
- 某卡片维度连续 2 轮零触发且被测面对应面无变化 → 移入 `test-suite/test-cases-archive/`（留作对照，退出执行范围）；
- 执行范围卡片数超过基线 × 1.5 时，结算前先强制一次合并/归档。

**结算日志**（写入 v(N+1) 头部，可审计）：本轮晋升（卡片号+理由）/ 合并（旧卡→新卡）/ 归档（清单+理由）/ 保持（说明）。

**种子闭环**：本轮真实缺陷**修复后**，凡通过"通用性"筛选的，同步进金丝雀语料（`test-suite/canary.md`，由产出元指标的金丝雀类成员维护）成为下轮种子——测试集与金丝雀共进化：抓过的坑变成家族的免疫记忆。

**结算自主但可回退**：旧版文件保留，用户否决某次结算 = 下轮直接沿用上一版文件，零损失。

## 红线

- 契约不清不设计：没有契约对照表先完成盘点（单独使用：读契约文档+双侧代码自行产出；总控执行：交回契约盘点环节），不裸设计；
- 只设计不执行：执行属于 exec 类成员；本技能产出必须可被用户/总控评审；
- 用例集不过名覆盖，上轮文件保留供回归对照；
- 破坏性/重启类卡片必须带"需还原"标记与还原命令，否则不允许进入用例集。

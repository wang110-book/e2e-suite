# 前后端联动 E2E 测试（总控编排 · 插槽式）

## 编排原则（解耦设计）

总控**不写死任何成员技能的名字**，只认 [suite-contract.md](references/suite-contract.md) 定义的家族契约：

- **阶段槽位**：env → design → exec → assert → report（custom 按 before/after 插入）；
- **成员自声明**：成员技能在自己的 SKILL.md 里放契约块（phase/inputs/outputs/before/after）；
- **产物衔接**：成员间只通过落盘产物耦合（上游 outputs 覆盖下游 inputs），不通过名字互调；
- **动态发现**：每次运行时扫描技能目录，凡带 `家族契约（e2e-suite）` 标记者自动入列——新技能接入零改动总控。

首次接入或对契约有疑问时，读 [references/suite-contract.md](references/suite-contract.md)。

## 编排流程

### Phase 0 接口契约盘点（联动测试的图纸，先于一切）
读 API 契约文档 + 前端请求代码 + 后端路由/解析代码，产出**契约对照表**：

| 前端动作 | 发出的请求（方法/路径/载荷字段） | 后端消费字段 | 后端证据通道 | 前端回显来源 |
|---|---|---|---|---|

- 已知高危区：载荷序列化（前端 stringify 与封装层是否重复）、字段名大小写/别名、后端"解析失败落默认值"的静默降级。
- 该表同时是执行类成员设计用例的输入与缺陷定位的对照基准。

### Phase 1 成员发现与排程
1. 扫描技能目录，收集带 `家族契约（e2e-suite）` 标记的成员；
2. 按 phase 默认顺序 + 成员的 before/after 生成执行计划，并做产物链匹配检查（上游 outputs 覆盖下游 inputs）；
3. **把发现到的成员名单与执行计划呈现给用户确认**后再执行；
4. 关键槽位（如 env/exec）无成员时：报告缺口并建议补充，不静默跳过。

### Phase 2 按计划调度执行
- 逐个成员通过 Skill 工具加载执行：env 类先跑，产物落盘；执行类成员吃环境说明产出联动测试集；
- 同 phase 多成员串行执行，或按用户点名裁剪；
- 每个成员结束后核对其 outputs 落盘，作为下游输入。

### Phase 3 联动层专属断言（成员技能之外，总控补齐）
1. **契约双向核对**：用 fetch 埋点抓前端发出的**载荷真身**，与后端实际消费的字段逐一对照（历史实证：双重 JSON 序列化让后端解析出字符串——UI 显示成功而功能落空）。
2. **部署一致性**：前端改动的代码必须在**实际承载它的产物**里验证（若编译嵌入服务端，改前端必须重编译服务端并核验版本/资源指纹）；浏览器缓存用版本化 query 破坏，验证时确认拿到的是新资源。
3. **双向往返闭环**：每个配置/状态类动作，验证"改完立即可见 + 服务重启/页面刷新后仍在"两个方向；反向（后端侧变化 → 前端正确反映）同样各测一轮。
4. **权限与降级联动**：未初始化/未登录/降权上下文下，前端引导（401→登录、403→注册）与后端状态码逐一对应。

### Phase 4 缺陷闭环
- 缺陷登记：现象（复现序列+载荷证据）/根因/修复。
- 修复后**重走编排**：重部署（前端改动→承载产物重建+缓存版本递增）→ 回归该用例 + 主链路冒烟 → 版本纪律（交付物版本号递增，禁止同名覆盖）。

### Phase 5 元验证与自进化（金丝雀）
assert 完成后，把本轮缺陷清单与金丝雀语料交给金丝雀成员（产出元指标的 custom 类成员）：种子命中/漏抓对账；漏抓 → 金丝雀成员产出"只增式进化提案"（diff+回退法，落进化日志），**由总控把提案应用到目标成员**（成员之间不互写定义），重放验证（重试上限 1 次，仍漏升级用户）；用户否决提案 = 按日志回退。产出元指标与进化记录。

### Phase 6 用例集结算（自主迭代）
把本轮新发现的可泛化用例/缺陷模式交给 design 类成员（产出用例集的家族成员），按其结算纪律（晋升三条件/防臃肿闸门/结算日志）生成 `test-cases-v(N+1)` 作为下轮回归基线；结算自主执行但结果记入报告，用户否决可回退（旧版保留）。

### Phase 7 报告
汇总各成员产出，在成员报告之上追加：契约对照表（含发现的契约错位）、双向往返闭环结果、部署一致性核验记录、本轮参与的成员名单与各自贡献、用例集结算记录（本轮晋升/合并/归档 + `test-cases-v(N+1)`）、元验证与进化记录（种子命中率/假绿样本/进化日志）。

## 编排红线

- 不跳过 Phase 0 直接开测——契约不清时，联动测试会退化成"点一遍看有没有报错"。
- 计划未经用户确认不执行——成员名单与顺序要透明。
- 成员产物不落盘不算完成——下游只认落盘产物，不认"我记得上一阶段做了什么"。
- 前端验证必须在真实承载产物上进行，宿主机开发目录里的"代码是对的"不算数。
- 用户的真实凭据与用户态数据全程不可破坏，测试结束必须还原验证。
- 家族自进化只增式 + 留痕（进化日志）+ 可否决回退；种子缺陷只注入夹具/桩层，**绝不注入被测系统代码**。

## 家族扩展指引（未来更丰富的形态示例）

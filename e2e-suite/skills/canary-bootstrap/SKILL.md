# 金丝雀语料引导（临时成员 · 自脱离）

## 家族契约（e2e-suite）

- phase: custom
- after: env
- before: exec
- inputs: 被测系统 env 说明（含**可控流源桩**开关清单）、契约高危区表、既有缺陷/种子来源（若有）
- outputs: `<被测系统>/test-suite/canary.md`（初版语料）+ `<被测系统>/test-suite/evolution-log.md`（空初始化）
- ephemeral: true            <!-- 临时成员，非长期在列 -->
- self-detach: on-completion <!-- 任务完成后契约块改名脱离家族名单，永久文件零留痕 -->

## 定位

`canary-calibration` 是**永久**成员，负责每轮"对账 + 自进化 + 元指标"；但它假设 `canary.md` 已存在（"首轮由本技能建"）。本临时成员补上**建**这一步，且**解耦**——允许在**不跑整轮 E2E** 的情况下先把金丝雀立起来（被测系统桩层已就绪、但还没到全量执行时）。

**干净原则**：本技能只产出**系统级资产**（`canary.md` / `evolution-log.md`），**不写入任何永久文件**（suite-contract、总控指引、其他成员 SKILL.md 一律不动）。执行完**自脱离**，故家族成员名单里不会出现它——这是刻意的。

## 流程

### 1. 判定与幂等
- 目标系统 `test-suite/canary.md` **已存在** → **增量模式**：只把新出现的桩开关/高危区补成新种子，**绝不覆盖/删除既有种子**；然后跳到第 5 步自检→自脱离。
- **不存在** → 新建模式，走 2-4。

### 2. 三源采集
- **源 A·桩开关**：从 env 说明的**可控流源桩**读开关清单（断流点/静默时长/终端事件开关/字段静默丢弃等）。每个**真实存在**的开关 → 一条种子。
- **源 B·契约高危区**：从契约对照表读"静默降级/假成功"等高危区 → 各生成 1-2 条**只读观测类**种子。
- **源 C·既有缺陷**：若该系统有已修复的真实缺陷清单 → 其中**通用性**成立的（可复用于同类系统）种子化。

### 3. 写 `canary.md`（每条种子四要素，与 canary-calibration 同 schema）
```
编号 / 注入点与开关 / 预期捕获通道 / 状态（驻留·每轮常开，标"种子（预期）"）
```
- **预期捕获通道必须是真实在列的成员**（流式类→streaming-channel-test；UI 假成功→blackbox-e2e-test；持久化→persistence-boundary-test；权限→negative-path-test）——**不得虚构不存在的成员**；拿不准就标"待 canary-calibration 首轮复核归因"。
- **只引用真实桩开关**：若该系统的桩层尚未就绪（env 说明里没有可控流源桩），**只建源 B 的只读观测种子**，并在文件头注明"桩层未就绪，语料限于只读观测类，待 env 交付可控流源桩后由下轮增量扩展"——**不得虚构尚未存在的开关**。

### 4. 初始化 `evolution-log.md`
表头 + 0 条：`| 日期 | 种子号 | 被改成员 | 条款 diff | 重放结果 | 回退方法 |`。

### 5. 自检（建完才删）
- 每条种子的"预期捕获通道"都是**现有**成员；每条注入点都是**真实**桩开关（或已标注"桩层未就绪"）；两个文件均已落盘。
- 自检**不过** → 停在原地报缺口（缺哪个桩/哪个成员不存在），**不脱离**（留着待补）。

### 6. 自脱离（干净收尾）
自检通过后，把本技能 SKILL.md 里的契约块标题
`## 家族契约（e2e-suite）` 改为 `## 家族契约（e2e-suite-暂停）`
（与 e2e-env-setup 同款机制——总控与 family_skills 只认前者，改名即脱离编排与发现名单）。
并打印确认："canary-bootstrap 已完成 <系统> 的金丝雀引导（N 条种子），已自脱离；永久文件零改动。"
改名**失败**（权限/路径）→ 明确报出失败原因，**不**假装完成。

> 为什么改名而不是删目录：本技能随插件装在缓存（`cache/e2e-suite/e2e-suite/<版本>/skills/`）
> 或 `~/.zcode/skills/`，删缓存文件会被下次更新/重新部署拉回，"永久消失"不成立；
> 契约块改名落在运行时副本上，脱离状态稳定，且即便文件被拉回，重触发也走第 1 步的
> 幂等增量（canary.md 已存在 → 补新种子 → 再次自脱离），无副作用。

## 红线

- **不写任何永久文件**（suite-contract / 总控指引 / 其他成员 SKILL.md）——只产出系统级 `canary.md` / `evolution-log.md`；改本技能自己的契约块不算写他人文件；
- **幂等增量**：重复触发绝不摧毁既有种子；
- **只引用真实**桩开关与真实成员，缺桩层则降级为只读观测类并显式注明，不虚构；
- 自检不过**不脱离**（保留待补）；
- 自脱离=契约块改名后从发现名单消失（与 e2e-env-setup 同款机制）；不得改动任何"入列"记录，也不得删除缓存文件（更新会拉回）。

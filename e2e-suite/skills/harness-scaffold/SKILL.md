# 测试脚手架生成（harness-scaffold）

## 家族契约（e2e-suite）

- phase: env
- before: design
- after: gate-preflight
- inputs: 被测项目根路径、技术栈说明（语言/测试框架/服务形态）
- outputs: `<项目>/tests/harness/`（或等价目录）+ `<项目>/docs/TESTING.md`（纪律）+ `<项目>/scripts/test.ps1|.sh`（统一入口，退出码 0/1/2）
- idempotent: yes（已存在则只补缺口与更新蓝图注记，不覆盖项目已改的模块）

## 存在理由

家族的执行类成员（blackbox/negative-path/visual-regression…）默认假设"项目有一套共享测试能力"。没有它，每个测试脚本各写一份 HTTP 客户端、各拼一份浏览器驱动、各硬编码一份凭据——这正是本项目体系化前的病灶：32 份 raw-socket 拷贝超时值三套、63 个脚本硬编码口令、24 个硬编码 npx 缓存绝对路径、门禁因无统一入口从未生效。脚手架把这些收敛成唯一实现，让"断言纪律"有机械落点（assert 库强制证据、skip 必带原因、退出码可被门禁消费）。

**与 gate 的分工**：本成员造场馆（测试基础设施），test-gate 当裁判（检测栈→跑→基线/抖动/回归拦截）。场馆建好后 gate 自动检测到，纳入门禁——闭环成立。

## 蓝图：八模块（项目无关的职责边界）

> 生成前先读 [test-namespace 规范](references/test-namespace.md)：测试文件放 `tests/<层级>/`
> （unit/api/e2e/ui），命名按各语言绑定表——写错位置的文件 runner 不会发现，等于没写。

生成时按语言栈选实现，但职责边界不变。参考实现见某 Windows 透明代理项目（Node/PowerShell 栈）的 `tests/harness/`。

| 模块 | 职责 | 通用性 | 关键坑注记（实测踩过的） |
|---|---|---|---|
| `ctl`（HTTP 客户端） | 与被测服务通信，能构造畸形请求 | 客户端通用、端点专属 | ① keep-alive 服务不能等 socket close 判完成，按 Content-Length **字节**判；② 流式响应禁止逐 chunk toString('utf8')——多字节跨段产生 U+FFFD 截断，必须 Buffer 累加、结算时一次解码；③ 无凭据时 requireToken() 在**发请求前**抛错，不去撞鉴权锁定 |
| `assert`（断言库） | 防空断言、失败带实际值 | 几乎纯通用 | "调用过即可/非空即可"是空断言；成功类断言必须校验内容与尺寸；证据参数必填非空 |
| `svc`（系统快照） | 服务/进程/端口/计划任务一次采集 | 半通用（实例名参数化） | 一次快照采全，避免断言间状态漂移；非提权读 SYSTEM 任务返回空 ≠ 不存在，与 schtasks 交叉验证 |
| `log`（游标日志） | 只认本轮产生的日志 | 通用 | 先取游标再查；秒级时间戳游标要回退 1 秒防同秒假阴性 |
| `net`（出口/连通证明） | 流量是否真走被测路径 | 通用（判据组合式） | 单靠 IP 变/单靠日志都不算证明，要组合；直连基准必须非空否则"IP 不同"无意义 |
| `ui`（浏览器驱动） | Web 界面自动化 | 通用 | 内核回退链（自带→系统 Edge/Chrome）；找不到明确报错不静默跳过；SPA 注入 localStorage 后必须 reload |
| `fixtures`（确定性夹具） | 替代数据来源，不替代渲染 | 模式通用、数据专属 | ① 桩存活靠 defineProperty(writable:false)（真实脚本会覆盖普通桩）；② 冻结页面时钟消除相对时间抖动；③ 字段名必须逐个与后端契约核对，编错键会让基线固化坏渲染 |
| `artifacts`（产物目录） | 每轮运行落盘证据 | 通用 | `<时间戳>-<层>-<主题>/` + manifest.json + 报告；"没测"≠"通过"，空层报 NOT-RUN 不报 PASS |

## 分层入口（test.ps1 / test.sh）

统一入口，退出码门禁可消费：**0=全过 / 1=有真失败 / 2=前置未满足**。三条铁律：
- 任一 FAIL 优先于 NOT-RUN（聚合码不能被"环境没备好"压住真红灯）；
- 碰全局态（配置/开关/任务）的层**串行**执行（并行文件互相踩踏全局状态，结论不可信）；
- 低层能测的绝不上高层：unit（纯函数）→ api（只打控制面）→ e2e（真实服务+驱动）→ ui（浏览器）。

## 纪律文档（生成到项目 docs/TESTING.md）

四条核心，全文见参考实现：
1. **CRUD/写操作**：PUT 200 ≠ 生效，写断言必须"写→读回→断言读回值"；写测试快照+after/finally 无条件恢复；免鉴权端点若有副作用按破坏性对待（负向凭据用例 ≤2 防锁定）。
2. **断言必须能红**：回归用例做变异验证（改坏实现→断言必须变红）。
3. **环境不满足 ≠ 通过**：skip 必带原因；skip 计 PASS 的框架要把"全 skip 层"报 NOT-RUN。
4. **诊断报告，测试判定**：取证脚本只报告不改状态、退出码只表达"跑完没有"、读不到显式标 UNAVAILABLE 禁止静默当正常。

## 流程

1. **侦查**：读项目现有测试脚本，统计重复面（几份 HTTP 客户端、几处硬编码凭据、有无统一退出码）——这是生成范围的依据，也决定优先收敛哪些模块。
2. **选栈**：按项目语言映射到蓝图实现（Node→参考实现直拷；Python/Go/其他→按职责边界重写，坑注记照搬）。
3. **生成**：建 `tests/harness/` 骨架 + 分层入口 + TESTING.md；专属模块（端点、夹具数据、实例名）留参数化插槽，标注"按本项目契约填"。
4. **接门禁**：脚手架就位后让 test-gate 重新检测（`test_gate_run`）；识别到 runner 即纳入。识别不到则检查锚点（如 C++ 栈需仓库根 CMakeLists + build 产物约定）。
5. **登记参考实现**：若这是该栈首个落地，把项目路径回写进本技能"参考实现"节。
6. **交回总控**：产出环境说明（脚手架清单+门禁状态+缺口），下游 exec 成员按契约生成用例。

## 边界

- 本成员造**结构与纪律**，不写**具体用例**——用例由 exec/design 成员按被测系统契约生成。
- 不搬别的项目的代码本体进新项目（含项目专属端点/凭据名）；搬的是职责边界与坑注记。
- 不碰被测系统运行时行为（那是 exec 与被测系统的事）。

## 参考实现

- **Windows 透明代理项目（Node 24 + PowerShell + C++/ctest）**：其 `tests/harness/` 八模块齐全 + `scripts/test.ps1`（四层入口）+ `docs/TESTING.md`（纪律全文：CRUD 八铁律 / 诊断五则）。视觉基线用 fixtures+冻结时钟方案，36 张基线进 git。该实现随项目私有，本蓝图是从中抽象的通用部分。

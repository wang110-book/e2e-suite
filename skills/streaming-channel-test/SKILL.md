# 流式与异步通道测试

## 家族契约（e2e-suite）

- phase: exec
- after: env
- inputs: 上轮通道矩阵（回归基线，可选）、环境说明（观测入口/凭据/夹具，**含可控流源桩**）、通道清单（SSE 端点/异步任务端点 + 事件定义 + 终端事件形态）
- outputs: 通道矩阵 + 成对证据（流原始记录文件引用 + 三路日志定位）+ 缺陷清单
- idempotent: yes（每条注入可复现可解除，结束清理流记录与异步任务残留）

## 定位

请求-响应型契约对照表覆盖不了"一条连接传 N 个事件"的通道。本成员回答四个问题：

1. 流**完整**吗：序列无丢、无重、终端事件正确；
2. 边界行为**符合声明**吗：断流/超时/静默期的处理是可预期的（降级/告警/断开），不是静默吞掉；
3. 断点定位**清晰**吗：出问题能从证据定位到 客户端↔代理 / 代理↔上游 哪一段；
4. 前端（若有）**如实呈现**吗：流未结束不报成功（假成功）、重连有可见状态。

## 通道矩阵

### 同步流（SSE / chunked）

| 边界 | 注入/操作 | 断言要点 |
|---|---|---|
| **首字节** | 正常请求，记录请求发出→首个 chunk 时间戳 | TTFB 证据记录（数值判定归性能探针类成员；本轮未排入则只记录不判定）；首事件形态符合契约 |
| **chunk 边界** | 上游夹具发：分隔符变体（`\n\n`/`\r\n\r\n`）、多行 data、UTF-8 跨 chunk 切分、超大单 chunk | 客户端收到的事件序列完整；编码无乱码；代理不截断/不改写 |
| **长连接保持** | 流静默 T 秒（夹具可控） | 心跳/keep-alive 策略符合声明；不静默断开，也不无限挂着 |
| **中途断流** | 夹具在第 M 个 chunk 后杀上游 | 代理侧关闭行为符合契约（错误帧/关闭码/超时阈值）；前端呈现断流态而非"成功" |
| **重连恢复** | 断流后客户端重连 | 若有 resume 机制（Last-Event-ID 类）验证续传点正确；无机制则记录为"已知限制"而非缺陷 |
| **超时策略** | 上游整体无响应 N 秒 | 代理超时断开并上报，不挂死；前端可见超时态 |

### 异步数据响应（任务队列 / 回调 / 轮询）

| 边界 | 注入/操作 | 断言要点 |
|---|---|---|
| **提交即见** | 提交任务 | 任务状态端点立即可见（queued/started 事件已发）；不出现"提交了查不到" |
| **完成一致** | 等待完成 | 结果内容 = 任务声明的预期产出；**三侧一致**：状态端点 / 结果内容 / 完成事件，任一不一致记缺陷 |
| **取消** | 任务运行中取消 | 状态机到 canceled；worker/临时文件/连接等资源回收（不残留） |
| **并发串扰** | 并行提交 N 个任务 | 每个任务的结果只含自己的数据（指纹标记法：任务参数里带唯一标记，回读结果核对） |
| **失败传播** | 夹具让某任务必败 | 失败原因正确传播到状态端点/事件流；不影响同批其他任务 |

## 取证纪律

- **流原始记录落盘**：完整 chunk 序列（时间戳/大小/内容指纹，可含内容原文到独立证据文件），报告只引用文件路径 + 关键位置，不内联全流；
- **三路交叉定位**：每条断流/异常结论必须带 客户端侧记录 + 代理日志 + 上游（夹具）日志 三方对照，定位到具体哪一段；
- **成对取证**：before/after 走同一通道同一口径（家族公共纪律）；
- 前端消费流时（若有 UI）：chunk 渲染正确、重连态可见、**流未结束却报成功 = 高危假成功**（家族公共口径：UI 表象≠功能生效）；
- 夹具死亡 ≠ 产品 bug：注入前查夹具自身日志与退出码。

## 交付物结构

```
<被测系统>/test-suite/streams-vN/
  matrix.md          ← 通道矩阵 × 结果（✓/✗/阻塞）
  evidence/          ← 流原始记录、三路日志片段、资源残留检查输出
  defects.md         ← 缺陷（现象复现序列 + 三路定位 + 严重度）
```

## 红线

- 注入（断流/超时/静默/失败）必须可复现、可精确解除：记录每条注入的开关与撤销方式，逐条撤销后复核通道恢复；
- 流记录与批量取证分批落盘，长连接录制不一次性 dump（大 I/O 纪律）；
- 异步任务测试结束清干净队列与 worker 残留，作为验收项写进收尾。

# 界面视觉设计审查

## 家族契约（e2e-suite）

- phase: exec
- after: env
- inputs: 环境说明（隧道/凭据）、（可选）产品设计 token 文件
- outputs: 视觉问题清单（截图证据 + 元素/CSS 定位 + 改法）、一致性审查表、四态完备性表
- idempotent: yes

## 定位：美观度怎么"测"

美观是主观的，但**好看的产品共同遵守的规则是客观的**。方法 = 三层替代主观感受：

1. **量化规则**：间距/字号/色彩/对齐是否符合设计系统惯例，可逐像素核查；
2. **完备性清单**：丑往往丑在"没被设计的状态"——默认浏览器控件、裸 alert、无空态；
3. **参照对比**：与优秀产品的同类界面并排比结构与层级，差距即问题。

参照基准（找差距用，不是照抄标准答案）：
- **国外**：Vercel / Linear / Stripe Dashboard（信息密度与克制）、Tailwind UI（组件形态）、Material 3 / Fluent 2 / Apple HIG（规则体系）；
- **国内**：Ant Design（企业中后台事实标准）、Arco Design、TDesign、飞书（密集信息布局）。

与 ux-acceptance-test 的分工：那边问"好不好用"（可用性），这边问"经不经看"（设计质量）。

## 审查流程

### 1. 截图矩阵
每个视图 × 主题（亮/暗）× 视口（1280 桌面 / 800 半屏 / 375 窄屏）截图，**用视觉逐张审查**（杂乱感、失衡、突兀色、层级不清、拥挤/空洞）——截图即证据，必须真实渲染而非读 CSS 想象。

### 2. 量化规则检查（从渲染结果与样式反查）

| 规则 | 检查点 | 常见问题 |
|---|---|---|
| **间距栅格** | 是否遵循 4/8px 体系；同类间距（卡片间/区块内）是否一致 | 5px、13px 的"手感值"散落 |
| **字体层级** | 字号/字重层级 ≤5 级且成比例；行高匹配 | 一屏 7 种字号、标题与正文只差 1px |
| **色彩系统** | 主色唯一、语义色（成功/警告/危险）用法一致；正文对比度 ≥4.5:1（WCAG AA）；暗色背景避免纯黑 | 同类元素两处颜色不同、暗色下灰字看不清 |
| **对齐** | 明显像素级错位；栅格列对齐 | 表头与单元格错位、卡片内容左缘不齐 |
| **组件形态** | 按钮/表格/表单/圆角/阴影跨页面同形态 | 同语义按钮三种圆角 |
| **视觉层级** | 每屏主操作唯一；重点信息有层级手段（大小/颜色/位置） | 满屏按钮全是同一个视觉权重 |
| **自定义变量可解析**（C-17） | 样式表内 `var(--x)` 的 `--x` 必须在设计 token 文件中定义；断言以 `getComputedStyle` 实测为准，不以"规则存在/类名存在"为凭 | 变量改名/删除后引用它的声明**整条静默失效**（IACVT）——如 `border: 1px solid var(--line)` 无报错地失去边框 |

### 3. 四态完备性（设计 Polish 的标志性检查）
每个数据视图四态齐全且**被设计过**：loading（骨架/指示器，非白屏）、empty（空态引导，非空白）、error（友好错误+重试）、success（反馈）。原始 alert/confirm、浏览器默认样式 = 问题。

### 4. 参照对比
拿同类信息架构的参照界面并排比对：信息密度、层级手段、留白节奏、操作位置——记录"参照产品怎么做、本产品差在哪、值不值得改"。**参照用于发现差距，不做像素级抄袭**。

## 输出

问题清单每条含：**截图证据（前后对照可选）→ 违反的规则/参照差距 → 元素或 CSS 定位 → token 级改法建议**（如"间距 13px → 12px，加入 --spacing-2"）。

## 红线

- 以"设计系统规则违规 + 参照差距"陈述问题，**不陈述个人口味**（"我觉得不好看"无效，"标题用了 7 种字号，惯例 ≤5 级"有效）；
- 只审查不改样式；用户确认后再出修复（修复后本技能回归截图对比）；
- 参照产品是基准不是标准答案——产品自己的设计 token 一致性优先于"像某个参照"。

# 视觉回归基线比对

## 家族契约（e2e-suite）

- phase: assert
- after: exec
- inputs: 环境说明（隧道/凭据）、基线库（首轮由本技能建立）、动态内容清单（时间戳/轮询数字/头像等）
- outputs: 基线库（按视图×主题×视口组织）、差异报告（diff 图 + 差异面积/阈值判定）、基线更新记录
- idempotent: yes

## 定位：与 visual-design-review 的分工

| | visual-design-review | 本技能 |
|---|---|---|
| 性质 | **审查**（发现设计问题，产出改法） | **守护**（守住已认可的样子） |
| 判据 | 设计规则与参照差距 | 与基线的像素差异 + 阈值 |
| 频次 | 大版本/设计改动时 | 每轮回归 |

流程闭环：审查提出问题 → 修复 → 用本技能建立新基线 → 之后每轮回归自动比对，界面被无意识改坏立即现形。

## 流程

### 1. 基线建立（首轮或设计变更确认后）
- 截图矩阵与 visual-design-review 同口径：每视图 × 主题（亮/暗）× 视口（桌面/半屏/窄屏）；
- 每张基线标注：视图名、视口、主题、建立日期、确认人（基线=被认可的界面快照，需人工确认）。

### 2. 动态内容遮蔽（防假差异）
比对前处理三类动态内容，否则每轮都是满屏假差异：
- **数据类**：时间戳、计数器、轮询数字、随机 ID → 遮蔽区域或固定夹具数据；
- **异步类**：加载指示器、动画帧 → 等待稳定后截图；
- **环境类**：滚动位置、光标焦点、系统主题差异 → 固定前置状态。

### 3. 差异比对与阈值判定
- 逐张与基线 diff：**像素占比必须脚本计算**（Node pngjs 或 PowerShell System.Drawing 等宿主原生手段；**不得由 LLM 或人眼估占比**），输出差异图 + 差异像素占比；LLM 只负责黄区（0.1%~1%）逐张复核；
- **阈值分级**：<0.1% 抗锯齿噪声放行；0.1%~1% 黄色待人工复核；>1% 红色判定为回归；
- 命中差异的先分类：**产品回归**（记缺陷）/**有意变更**（走基线更新确认）/**遮蔽遗漏**（补遮蔽规则）。

### 4. 基线更新（唯一改基线的路径）
- 有意变更（设计改动/缺陷修复后的新样子）→ 用户确认新截图 → 替换基线并记录变更原因与日期；
- 基线库纳入版本管理；基线更新记录 = 界面演进史。

## 红线

- 阈值判定以**脚本算出的像素占比**为准，"肉眼看着像→放行"禁止——那样三级阈值就只是纸面数字；
- 基线必须人工确认后才生效——自动建立的首轮截图只是候选；
- 遮蔽规则优先于阈值调整：差异频出先想"该不该遮"，不是无脑放宽阈值；
- 与功能回归独立：界面没变不代表功能没坏（交 blackbox-e2e-test），功能没坏也不代表界面没走样（本技能补位）。

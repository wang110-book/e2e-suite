## 七步流程

### 1. 侦查（只读，先看后动）
- 部署形态：服务名/进程名、版本、自启方式、端口（`sc query` / `systemctl` / `netstat` / 配置文件）。
- 数据位置：配置文件、数据库、日志路径与轮转方式。
- 鉴权方式：默认密码？未初始化态？改密入口？
- **在动手改任何东西之前完成本步并记录**。

### 2. 访问通道
```bash
ssh -L <本地端口>:127.0.0.1:<服务端口> user@远程机 -f -N
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:<本地端口>/   # 验证
```
- 服务仅绑回环 = 产品安全设计，**用隧道而非改产品绑定**；替代：管理员 netsh portproxy。
- 隧道进程用 `-f -N` 后台化；验证方式：宿主机 `netstat` 看监听者是 ssh.exe。

### 3. 备份（还原是验收的一部分）
- 配置文件、数据库（含 WAL/侧文件）、状态文件全量拷贝到测试目录。
- 数据库在服务运行中需先停服再拷（WAL 未合并）；记录还原顺序。

### 4. 注入测试态
- **测试凭据**：清空/重置后用已知测试密码初始化，绝不占用用户真实凭据；还原后用户密码必须原样可用。
- **样例数据**：通过 API 或直接落盘注入最小可控数据集（假账号/样例文件/边界数据）。
- **桩服务**：核心依赖不可控时起假后端（正常/拒绝/超时三种形态至少各一），用于正反用例。

### 5. 夹具生命周期
- 常驻方式：远程常驻会话 / 计划任务 / systemd；**异步启动必须轮询等待**，不用固定 sleep。
- 状态残留：任务卡 Queued/Running 且无进程 → 实例状态未清理，先 End/杀实例再重启。
- 夹具日志独立存放；**夹具死亡 ≠ 产品 bug**，先查夹具自身日志与退出码再下结论。

### 6. 观测预置
- 确认：服务日志路径与轮转、DB 只读查询方式、状态/调试 API。
- 崩溃类测试前先开崩溃转储（Windows: WER LocalDumps DumpType=2；Linux: coredump ulimit/pattern）——**先布防再复现**。

### 7. 收尾还原
- 停夹具进程与任务 → 停服务 → 还原备份（按记录顺序）→ 起服务。
- 验证用户态：用户凭据可用、开关/配置原样、版本正确。
- 清理测试痕迹（测试文件/临时账号/转储保留策略）；交付**环境说明**：隧道端口、测试凭据、夹具清单、备份位置、还原命令。

## 通用坑清单（实战沉淀）

- SSH 会话里的进程随会话回收（job object）——常驻用计划任务/systemd 或保持会话；复用已认证 SSH key 免交互。
- PowerShell 远程执行：SSH exec 默认 cmd shell，复杂命令写 .ps1/.bat 上传；`$_`/`$var` 在宿主双层引号里会被本地展开。
- 分发脚本：Windows PowerShell 5.1 对无 BOM 文件按 GBK 解析——分发 .ps1 一律纯 ASCII 或 UTF-8 BOM。
- 权限验证需降权上下文（runas /trustlevel 或普通账户），管理员会话测不出普通用户被拒的场景。
- 远程 IP 会漂移：用 SSH config Host 别名；IP 变了只改一处。

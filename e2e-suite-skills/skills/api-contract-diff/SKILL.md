# API 契约漂移检测

## 家族契约（e2e-suite）

- phase: assert
- after: exec
- before: report
- inputs: 接口契约文档（API.md/OpenAPI/请求示例）、前端请求代码、后端路由/解析代码、（可选）运行中的测试环境
- outputs: 契约对照表 + 漂移清单（四方比对、严重度分级）+ 修复建议
- idempotent: yes（动态探测以只读端点为主，写端点仅在测试环境）

## 定位

契约错位类缺陷（双重序列化、字段名不符、前端读了后端从不发的字段）在黑盒测试里表现为"诡异的假成功"，根因很难猜。本技能把"猜"换成"四方比对"：**文档、静态实现、运行时行为、前端消费**，任何两方不一致即漂移。

## 四方取证

| 来源 | 取证手段 | 提取内容 |
|---|---|---|
| ① 契约文档 | 读 API.md/OpenAPI/接口示例 | 端点矩阵：方法/路径/请求字段/响应字段/状态码 |
| ② 后端实现 | 读路由注册与解析代码 | 实际注册的端点、实际消费的字段、内部字段剔除/默认值降级逻辑 |
| ③ 运行时行为 | 对每个端点发探测请求（合法/缺字段/错类型/多余字段/错方法） | 实际状态码、实际响应字段、错误结构 |
| ④ 前端消费 | 读前端请求/解析代码 + fetch 埋点抓载荷真身 | 前端实际发出的字段、实际读取的响应字段 |

## 比对矩阵（五类漂移）

1. **文档 ↔ 实现**：文档写了没实现（幽灵端点）、实现了没写（隐藏端点）、字段名/类型/必选性不一致；
2. **实现 ↔ 运行时**：代码看着对但行为不对（解析降级、版本未部署）；
3. **前端 ↔ 实现**：前端发出的载荷后端不认（序列化错位）、前端读取的字段后端不发（永远 undefined）；
4. **文档 ↔ 前端**：前端按旧文档写的消费逻辑；
5. **语义漂移**：字段都在但含义变了（枚举值、状态码语义、默认值）。

## 严重度分级

- **高危**：前端消费的字段/语义漂移（直接造成假成功或假失败）；
- **中**：文档与实现漂移但行为一致（误导后续开发）；
- **低**：响应多余字段、错误信息措辞。

## 输出

1. **契约对照表**（联动测试总控 Phase 0 的自动化输入）：前端动作 × 载荷字段 × 后端消费 × 证据通道 × 回显来源；
2. **漂移清单**：每条含四方证据原文、漂移类型、严重度、修复建议（改文档/改实现/改前端三选一的判断）；
3. 双用途说明：既可在 exec 前运行生成契约对照表（总控 Phase 0 的输入），也可在 exec 后运行作为回归比对。

## 红线

- 探测以只读端点优先；写端点探测仅在测试环境且用测试凭据；
- 不猜契约——每条结论必须有文档/实现/运行时至少两方证据；
- 生产环境只做只读探测，禁用写端点探测。
